<objective>
Install the static half of the engine's determinism guarantee — a lint rule banning `Date`, `Math.random`, `crypto`, `Intl` and `toLocale*` inside `packages/engine`, and a dependency-cruiser rule keeping the currency-formatting module out — and prove each ban fires against a fixture built to violate it.

Purpose: Phase 1 shipped four checks that passed while inspecting nothing. Success Criterion 2's locale leg cannot be tested by flipping an environment variable, because research verified on this machine that `LANG` does not move Node's `Intl` default locale — a runtime flip would pass while testing nothing, which is the same failure again. Static analysis is the substitute, and it is only worth anything if it is shown catching something.

Output: gates that have been observed failing on purpose.
</objective>

  <action>
Edit `eslint.config.js`.

First, lift the three AC-07a money-brand selectors out of the inline array into a module-level `const MONEY_BRAND_SELECTORS = [...]` so they can be referenced from more than one config entry without a second copy. Leave the existing cross-package entry (`packages/engine` + `packages/schemas`) spreading that array, so nothing about AC-07a's current behaviour changes for `packages/schemas`.

Then add a **second** flat-config entry scoped to `packages/engine/**/*.ts` only, carrying:

  - `no-restricted-globals`, with one entry per banned global and a distinct message for each, so a test can tell which ban fired: `Date` (the engine reads time only through the injected `now` — PRD §8.1), `Intl` (locale-dependent output would make the same input produce different results on a different host), `crypto` (identifier minting must be derived from inputs, not random).
  - `no-restricted-properties`, banning `Math.random` with its own message. This is a separate rule from `no-restricted-globals`, not a second entry within it — `Math` itself is legitimate and must stay usable, because `Math.floor` is the rounding discipline the whole money path depends on.
  - `no-restricted-syntax`, spreading `MONEY_BRAND_SELECTORS` **plus** one additional selector matching a member expression whose property name begins with the locale-formatting prefix, with its own message.

The `no-restricted-syntax` spread is the load-bearing detail. ESLint flat config resolves a rule by replacing its options from the last matching config object, not by concatenating them. An engine-scoped `no-restricted-syntax` entry that carried only the locale selector would silently switch AC-07a's money-branding rule **off** for every file in `packages/engine` — the gate would keep running and keep reporting zero problems, which is exactly the Phase 1 failure mode this phase exists to stop repeating. Task 2 asserts against that regression directly.

Do not add an `eslint-disable` anywhere in `packages/engine` to accommodate any of these bans. If a module appears to need one, that is the escalation signal, not a formatting problem.

Run `pnpm run lint` and confirm it exits 0 against the tree as it stands.
  </action>

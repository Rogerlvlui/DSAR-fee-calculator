Create `packages/engine/src/apply-cap.ts` exporting `applyCap(cap, line)` returning a branded `Minor`.

Per cap type, from research Pattern 2's analysis of the frozen `CapSchema`:
  - PER_UNIT: `cap.amount * line.quantity`. Both operands are already integers, so the product is exact and needs no rounding.
  - PER_LINE: `cap.amount` directly.
  - PERCENT_OF_CLAIM: floor of `(claimedAmount * percent) / 100`. Multiply before dividing, and floor once at the end. The percent is not constrained to an integer by the frozen schema, so a pack author may legally author a fractional one; the intermediate value is therefore not integral even though the result must be. Use flooring, never rounding, anywhere in this chain — AC-07c's "33, not 34" exists specifically to catch a rounding substitution, and PRD §8.1's closing line makes rounding down the rule for the whole money path.
  - PER_MATTER: raise a typed error. A per-matter cap is an aggregate over every line, and a function with a single line's data cannot evaluate it correctly. The frozen schema permits the combination structurally, so a stub or authored pack could ship it; the engine must refuse rather than silently treat it as a per-line figure. Record in a comment that Phase 3's pack validator should reject this combination at build time too, so it never reaches a runtime that has to throw.

Every return is `min(claimedAmount, cappedFigure)` — a cap reduces, never increases.

Create `packages/engine/src/conditions.ts` exporting `evaluateConditions(conditions, { line, matter })` returning `{ met: boolean; failed: Condition[] }`. Resolve each condition's `field` against the line first and the matter second, using the closed `CONDITION_FIELDS` vocabulary from `@dsar/schemas/condition` — import the constant, do not restate the list. Support all three union arms and all six comparison operators plus `in`, `isNull` and `isNotNull`. An empty condition array means met. Comparison is strict: no coercion between a string and a number, because a silently coerced comparison is a rule applying differently than a pack author wrote it. Return the failing conditions themselves rather than stringified descriptions, so the caller can render which ones failed without re-deriving them.

Add the two new error codes to `packages/engine/src/errors.ts` and their message text to `packages/engine/src/messages.ts`.

Write `packages/engine/src/apply-cap.test.ts` and `packages/engine/src/conditions.test.ts` first, red, covering every behaviour above plus §14's named boundary cases.

# Phase 7.1 — UI Design Contract

> Visual and interaction contract for the Claude Design adoption restyle. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder (from 07.1-CONTEXT.md):** restyle HR intake, Legal review, and HR result/notice
to the Claude Design export's actual tokens and markup; add a new, additive Audit trail screen.
PRD §10.6 Rule pack admin stays out of scope, deferred not dropped. No regression in Phase 4–7
tests (D-4) — this is a restyle plus one addition, not a rebuild.

**Headline finding from this research:** the Claude Design export's colour palette is a byte-for-byte
match to `apps/web/app/globals.css`'s existing tokens (`--color-seal:#7c2334`, `--color-ok:#1c6146`,
`--color-warn:#8a5a06`, `--color-stop:#a32020`, `--color-deny:#565f6c`, `--color-ground:#eef0f2`,
`--color-ink` family, `--color-line` family — all identical hex values). **The real delta this phase
must deliver is typography (three named webfonts, not system stacks) and markup/structure**
(numbered-step intake sections, left-accent-bar review cards, letter-styled notice document, the
verdict→colour mapping correction below), **not a colour overhaul.** Plan and scope accordingly.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-authored CSS (Tailwind v4 `@theme` + `@layer components`, per the existing `globals.css` pattern) |
| Icon library | none — the design uses text, Unicode glyphs (`↳`, `•`, smart quotes) and coloured accent bars/badges, never an icon set |
| Font | Newsreader (serif — display/headings, plus one italic quote style) · IBM Plex Sans (sans — body/UI) · IBM Plex Mono (mono — money figures, rule IDs, timestamps) |

**Why not shadcn:** seven prior phases (3.1 through 7) built and restyled four screens entirely on
hand-authored Tailwind v4 tokens with no component library, and D-1 only mandates that the *visual
result* come from the Claude Design export, not that the implementation mechanism change. Introducing
a component library now would be a large, unscoped deviation for a demo-deadline restyle phase and
buys nothing the existing token+component-layer pattern doesn't already provide. Reversible later if
a future phase (e.g. the deferred Rule pack admin screen) wants richer form primitives.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 11px (0.6875rem) | 600 (semibold) | 1.3 |
| Body | 14px (0.875rem) | 400 (regular) | 1.5 |
| Heading | 16px (1rem) | 600 (semibold) | 1.3 |
| Display | 24px (1.5rem) | 600 (semibold) | 1.2 |

This is the same four-role, two-weight scale already frozen in `globals.css` (03.1-UI-SPEC's
contract) — unchanged, because it already accommodates every text size the design export actually
uses once consolidated. **Do not add a fifth size or a third weight**; the design's own granular
sizes (10/10.5/11/12/12.5/13/13.5/14.5/15/16.5/17/19/20/21/25px) and its occasional `font-weight:500`
all collapse into the four roles and the 400/600 pair below, per the existing discipline.

**Weight collapse rule:** every `font-weight:500` instance in the design source (nav buttons, table
labels, quantity/rate fields) renders at **600**, not 500. The visual difference at these sizes is
negligible and a third weight is not worth breaking the frozen two-weight contract for.

**Named typefaces — self-host, do not link Google Fonts at runtime.** The design's own `<helmet>`
block links `fonts.googleapis.com` directly; **do not port that link into `apps/web`.** Use
`next/font/google` (Next.js 16, already the installed framework) to fetch and self-host the font
files at *build* time — this satisfies Roadmap success criterion 1's requirement to use the actual
named typefaces (Newsreader / IBM Plex Sans / IBM Plex Mono) while making zero runtime network
requests to a third party, preserving the same "no live outbound fetch" property the prior
system-font-stack decision existed to guarantee (originally a Phase 3.1 offline-demo constraint,
still worth keeping). **Risk to flag for planning:** `next/font/google` needs network access once,
at build time, to fetch the font files — verify build-machine network reachability before relying on
it; if blocked, vendor the static font files locally and declare them via `@font-face` instead.

Load only the weights the two-weight contract actually needs — **400 and 600** for IBM Plex Sans and
IBM Plex Mono, and **400 (incl. italic) and 600** for Newsreader — not the full 400/500/600(/700) set
the design's own Google Fonts link requests. The one deliberate exception: the review card's quoted
"HR's description" text renders in **Newsreader italic at the Body (14px) size** — the only place body
text switches to the serif family; this is intentional design texture carried from the export
verbatim, not a new size or weight.

Declared font-family tokens (fallback stacks preserved from the current `globals.css` for
resilience if a self-hosted font fails to load):

```
--font-sans:  "IBM Plex Sans", ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif;
--font-serif: "Newsreader", ui-serif, Georgia, "Times New Roman", serif;
--font-mono:  "IBM Plex Mono", ui-monospace, "SFMono-Regular", Menlo, monospace;
```

Money figures, rule IDs and timestamps use `var(--font-mono)` with `font-variant-numeric:
tabular-nums` regardless of which size role they inherit — this is the existing `.fig` class pattern
and does not change.

## Spacing Scale

Declared values (multiples of 4, carried forward unchanged from the current `globals.css` — already
proven to accommodate the design's granular padding values via the rounding rule below):

| Token | Value | Usage |
|-------|-------|-------|
| 2xs | 4px | Icon/glyph gaps, tightest inline padding |
| xs | 8px | Compact element spacing, small button padding-block |
| sm | 12px | Row/list-item gaps, badge padding |
| md | 16px | Default element spacing, card section padding-inline |
| lg | 20px | Card body padding, form field gaps |
| xl | 24px | Section-level gaps, grid gaps |
| 2xl | 28px | Card outer padding |
| 3xl | 32px | Page-section spacing, document padding |
| 4xl | 48px | Major section breaks |
| 5xl | 64px | Page-level spacing |

**Rounding rule for design-sourced values that aren't already a multiple of 4:** round to the nearer
token; on an exact tie, round up. Worked examples from the actual design source: `5px→4 (2xs)`,
`7px/9px→8 (xs)`, `10px/11px/13px→12 (sm)`, `14px/15px→16 (md)`, `18px→20 (lg)`, `22px→24 (xl)`,
`26px→28 (2xl)`, `30px/36px→32 (3xl)`.

**Exceptions:** one-off, non-repeating page-wrapper values that are already a clean multiple of 4
(e.g. the design's 80px page bottom-padding) may be used literally without forcing them through a
named token — the "multiples of 4" rule constrains the *value*, not which values must carry a name.
Border-radius, border-width and box-shadow stay plain literals (as today), since the theme declares
no token for any of the three.

## Color

Palette is unchanged from the current `globals.css` tokens — confirmed identical hex-for-hex against
the design export. Restated here as the frozen contract for this phase, with corrected reserved-for
lists (see the verdict-colour correction below).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#eef0f2` (`--color-ground`) | Page background only |
| Secondary (30%) | `#ffffff` (`--color-surface`) | Card/panel surfaces — plus supporting shades `#f5f6f8` sunk zones (claim footer, expense-line rows, totals highlight), `#d8dce1` border, `#e6e9ed` soft border/divider |
| Accent (10%) | `#7c2334` (`--color-seal`) | See reserved-for list below |
| Destructive | `#a32020` (`--color-stop`) | See reserved-for list below |

**Accent (`--color-seal` `#7c2334`) reserved for:** primary CTA buttons only — "Submit to Legal",
"Go to sign-off", "Sign off and release to HR", "Draft the query email to Legal", "Copy the email";
the kicker/eyebrow uppercase label colour; the wordmark's accent full stop; hyperlinks; the
`:focus-visible` ring; the sign-off block's left accent border and header band; the "Notice of fee"
label on the requestor notice. Never a default/hover tint on ordinary secondary controls.

**Destructive (`--color-stop` `#a32020`) reserved for:** the Strike button's hover/text state; the
two blocking-error banners ("no lawyer sign-off recorded — nothing to notify" on the notice screen,
and the currency-mismatch validation error); and the "no fee basis" badge shown only when the
posture gate itself has ruled out any fee basis for the jurisdiction (`NO_EXPRESS_AUTHORITY` /
`PROHIBITED`, mapped to a `DISALLOW` verdict produced by the posture gate rather than a per-line
rule). **Never** the everyday `DISALLOW` verdict badge — see the correction below.

**Additional — verdict/status semantics** (a fourth colour category, distinct from accent/destructive;
every one of these ships with a required visible text label per DISC-04/WCAG 2.1 AA — colour is
never the only signal):

| Role | Value | Reserved for |
|------|-------|--------------|
| Warn | `#8a5a06` text / `#fbf1de` wash / `#e0b869` edge | `FLAG` verdict pill ("Needs your decision"), the "Other claim — referred to you" badge, matter-level flag callouts (rule-pack-review-due, dispute, other advisories), stale-pack banners, the intake "Heads up — {jurisdiction}" posture notice |
| OK | `#1c6146` text / `#e8f2ed` wash | `ALLOW` / `ALLOW_CAPPED` verdict pills ("Supported by rule" / "Supported — reduced to cap"), the revealed recommended-fee panel once every line is decided, the categorised-lines summary card |
| Deny | `#565f6c` text / `#eceef1` wash | `DISALLOW` verdict pill ("Not supported") in the **ordinary** case — a specific category rule disallows the line, not a jurisdiction-wide posture block |

**Correction the executor must apply:** the current `globals.css` pill rule maps
`article[data-verdict="DISALLOW"]` to the Destructive (stop/red) wash. The design's own review-card
treatment uses **Deny (grey)** for the everyday "Not supported" badge and reserves Destructive
(red) for the jurisdiction-level no-fee-basis case described above. Re-point the `DISALLOW` pill rule
to the Deny role; the "no fee basis" case is a `DISALLOW` verdict produced specifically by the posture
gate and should carry an additional visual distinction (e.g. a data attribute or badge-text
difference already possible via the existing flag/reason text) rather than sharing Deny's tint.

## Screen-by-Screen Structural Notes

Not a template section, but load-bearing for planning — the colour/type/spacing tokens above are
necessary but not sufficient; the design's markup restructures each screen materially.

**HR intake (`/hr/matters/new`).** Adopt the design's numbered-step section headers (a small
monospace square badge — "1", "2", "3" — followed by the section title, e.g. "1 Matter details").
Add the design's third section, "How the engine sorted these lines" (categorised vs. Other-claims
split cards), which restates INTAKE-06's existing category hints in a new visual frame — no new data
or behaviour, purely a restyle of what the intake form already computes.

**Legal review (`/legal/assessments/{id}`).** Adopt the design's left-edge 3px accent bar per card
(colour keyed to verdict, using the corrected OK/Warn/Deny/Destructive mapping above) in place of
the current whole-card background wash for decided lines. Badge label text changes to the design's
exact wording ("Supported by rule", "Supported — reduced to cap", "Not supported", "Needs your
decision") — these are copy changes, not behaviour changes; DISC-04's "verdict in words" requirement
is unaffected since it already requires exactly this. The right-rail sign-off panel adopts the
design's maroon header band and serif attestation-text card — the attestation content itself
(rendered by `renderAttestation()`) is untouched.

**HR result / Fee notice (`/hr/matters/{id}`).** Adopt the design's document-styled notice — a
white card with its own internal header (entity name, "Notice of fee — data access request" label,
matter ref + signed-at date), a bordered line-item table, a basis paragraph, and a
reviewed-by/qualification footer block. This is the existing `notice-block.tsx` content, restyled
into a letter format; DOC-02/DOC-03's content constraints (no rule ID, no citation, no AI mention in
the notice body) are unchanged and must still hold under the new markup.

**Audit trail (new screen) — structural adaptations the design's single mock table doesn't show:**

1. **Route and gating:** `/admin/audit`, gated `requireRole(actor, "DPO_ADMIN")` — the same
   first-statement pattern `exportAuditLog()` already uses (`apps/web/src/server/data/audit.ts`).
   Re-add `DPO_ADMIN` to the app header's `ACTOR_OPTIONS` role switcher — it was deliberately left
   out in Phase 4 P03 specifically because no screen existed yet for it; one now does.
2. **Scope is the whole log, not one matter.** The design's screen header reads "Audit trail —
   {matter ref}" and is scenario-filtered client-side, but the real `exportAuditLog()` has no
   matter parameter — it returns every matter's events (AUDIT-04: "the DPO can export the audit
   log"). Build this as a global log view, and add a **Matter** column (matter reference/id) per
   row so a reader can tell which matter each event belongs to — a structural addition beyond the
   design's literal markup, required because the underlying capability is whole-log, not per-matter.
3. **Two streams, not one.** `exportAuditLog()` returns `matterEvents` (`AuditEvent[]`) and
   `packLifecycleEvents` (`PackLifecycleEvent[]`) as two separate arrays — D-21's deliberate choice
   to keep pack-lifecycle events off the widened `AuditEvent` schema. Render as two stacked tables
   under one "Audit trail" heading ("Matter events" / "Pack lifecycle events"), not a single
   interleaved table the schemas don't support merging into.
4. **Drop the "Hash" column — do not fabricate one (D-3).** `AuditEvent` has no hash field; nothing
   in `packages/audit` computes or verifies a chain today. Replace the design's rightmost "Hash"
   column with two real, already-captured fields instead: **Pack** (`rulePackVersion`) and **Engine**
   (`engineVersion`), rendered as an em dash when `null`. This keeps the same "provenance" reading the
   design was gesturing at without implying an integrity guarantee the system doesn't provide — the
   same "never overstate what the tool actually does" instinct as the banned-words rule elsewhere in
   this product. If real hash-chaining is added to `packages/audit` in a future phase, the column can
   return with real data then.
5. **Table columns (matter events):** Seq · Timestamp · Matter · Actor · Event · Detail · Pack ·
   Engine. Widen the design's `min-width: 720px` horizontal-scroll wrapper to accommodate the added
   Matter/Pack/Engine columns (recommend `min-width: 900px`). Detail text should compose from the
   event's `payload` (field/before/after/entityId) in plain words — do not render the raw JSON
   payload object.
6. Do **not** build the design's scenario switcher, mock-banner toggle, or scenario-scoped state —
   confirmed by CONTEXT.md as a prototyping convenience only.

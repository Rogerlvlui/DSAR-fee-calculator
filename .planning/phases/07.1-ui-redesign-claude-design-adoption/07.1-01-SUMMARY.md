## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `next/font/google` resolves to `undefined` outside Next's build-time compiler transform, breaking `tests/routes/honesty.test.ts`**
- **Found during:** Task 1, running the full `pnpm test` suite
- **Issue:** `tests/routes/honesty.test.ts` renders the real root layout directly under Vitest (needed to prove the permanent no-persistent-data marker's DOM position). Once `layout.tsx` called `next/font/google`'s loaders at module scope, the "routes" Vitest project's plain Node import of that module returned no callable exports (`TypeError: IBM_Plex_Sans is not a function`) — Next's real font-loader transform only runs inside its own webpack/SWC compiler pipeline.
- **Fix:** Added `tests/fixtures/next-font-google-mock.ts` (a minimal stub returning the same `{className, variable, style}` shape) and aliased `next/font/google` to it via `resolve.alias` on the "routes" Vitest project only — the sole project importing `layout.tsx` directly.
- **Files modified:** `tests/fixtures/next-font-google-mock.ts` (new), `vitest.config.ts`
- **Verification:** `pnpm vitest run --project routes -t "HONESTY"` passes; `pnpm test` full suite green.
- **Committed in:** `527dda7` (Task 1 commit)

**2. [Rule 3 - Blocking] `next/font/google` also fails to resolve under `tests/tsconfig.json`'s inherited "nodenext" module resolution**
- **Found during:** Task 2, running `pnpm run typecheck` to confirm no regression
- **Issue:** `next` ships no `package.json` "exports" map, so `nodenext`'s ESM-mode resolution cannot resolve any `next/*` subpath without an explicit file extension — the exact, already-documented gap `tests/tsconfig.json`'s own comments record for `next/navigation`/`next/headers` (why `current-actor.ts`/`intake-form.tsx` are excluded from that project). `apps/web/app/layout.tsx` cannot be excluded the same way: `tests/routes/honesty.test.ts` imports it directly, and TypeScript requires every directly-or-transitively-imported file to resolve.
- **Fix:** Added an ambient module shim (`tests/types/next-font-google.d.ts`, auto-picked up by the project's own `**/*.ts` include glob) declaring the three loaders' minimal call shape. `apps/web`'s own `tsc -p apps/web/tsconfig.json` run (bundler resolution) and the real `next build --webpack` both resolve the genuine types/behaviour, unaffected by this shim.
- **Files modified:** `tests/types/next-font-google.d.ts` (new)
- **Verification:** `pnpm run typecheck` clean; `npx tsc -p tests/tsconfig.json` clean in isolation.
- **Committed in:** `64c31bc` (Task 2 commit)

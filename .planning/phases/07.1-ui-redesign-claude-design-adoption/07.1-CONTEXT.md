# Phase 7.1: UI Redesign — Claude Design Adoption - Context

**Gathered:** 2026-09-23, in conversation ahead of a Friday demo (not via a formal `/gsd-discuss-phase` session — `gsd-tools.cjs` is unavailable in this worktree, same recurring gap recorded for Phases 3–5; decisions below were made directly with the product owner and are reproduced here so the UI researcher does not re-ask them)

<domain>
## Phase Boundary

Restyle `apps/web`'s four already-built PRD §10 screens (HR intake, Legal review, HR result, and the notice view) to match the Claude Design export's actual visual system, and add one new screen (Audit trail) that exists in the design export but not in the PRD.

**In scope:** design tokens (colour, typography, spacing) and markup structure sourced from `docs/design/`; the Audit trail screen as new, additive UI (read-only event log); WCAG 2.1 AA and no-colour-only-verdict compliance under the new system.

**Not in scope:** PRD §10.6's Rule pack admin screen (deferred, tracked separately, not dropped); any change to application/business logic, the engine, schemas, or persistence; hash-chaining the audit log for real (the design's "hash" column is a visual proposal only — see Deferred).
</domain>

<decisions>
## Implementation Decisions

- **D-1: Build from the Claude Design export directly, not through Tailwind.** Product owner's explicit instruction: "use design from Claude Design, not from Tailwind." The current `apps/web` styling (Tailwind v4 utility classes, fixed in the 2026-09-22 quick task) is being replaced as the source of visual truth — the design tokens and markup in `docs/design/dsar-fee-agent-claude-design.dc.html` (and its rendered/standalone-src siblings) are authoritative now. Whether the *implementation* mechanism remains Tailwind (config'd to emit these exact tokens) or moves to something else is an implementation decision for research/planning — the constraint is the visual *result* must come from the design export, not be a Tailwind reinterpretation of it. — **Reversibility:** reversible (a styling-layer choice).

- **D-2: Audit trail is new scope, not a substitute.** The design export's 4th screen ("Audit trail") does not match PRD §10.6's actual 4th screen ("Rule pack admin"). Confirmed with the product owner via direct question: treat Audit trail as a genuine new screen/feature to add, alongside the three screens the design does match (HR intake, Legal review, HR result/notice). Rule pack admin stays deferred, explicitly tracked, not silently dropped. — **Reversibility:** reversible (additive).

- **D-3: The design's hash-chained audit log is a visual proposal, not a confirmed feature.** The rendered design shows a "hash" column on the Audit trail screen implying cryptographic event-chaining. No such capability exists in `packages/audit` today (it's an append-only writer, not a chained/hashed one). This phase's UI-SPEC should note the column as an open question for planning — build the visible surface, but do not assume real hash-chaining is in scope for the UI screen to actually compute/verify (see Deferred).

- **D-4: No regression tolerance.** This is a restyle plus one addition, not a rebuild. Every currently-passing test (Phases 4–7, including all seven §10.7 edge states) must keep passing. The UI-SPEC should treat this as a hard constraint on the researcher's recommendations — e.g. don't recommend a framework/library change that would require touching route/data logic.

</decisions>

<specifics>
## Specific Ideas

- The design export includes a built-in scenario switcher (SG-other-claims / SG-flagged-lines / CN-no-fee-basis) purely for prototyping — this is a design-tool convenience, not a feature to build into the real app.
- Design tokens observed directly from the export: accent `#7c2334` (maroon), body text `#171b22`, background `#eef0f2`, fonts Newsreader (serif headings), IBM Plex Sans (body), IBM Plex Mono (money/mono figures) — these are largely consistent with the palette already applied in the 2026-09-22 quick task, which may make this more of a refinement than a from-scratch rebuild. Verify this directly against `globals.css` during research rather than assuming.
</specifics>

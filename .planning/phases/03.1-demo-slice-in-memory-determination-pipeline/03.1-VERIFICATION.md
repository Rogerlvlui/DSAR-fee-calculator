### New Finding From This Round's Live Testing (not a gap against SC-1, flagged for completeness)

While driving the live walkthrough, `GET /assessments` (and, by the same code path, any role-gated Server Component page) was also probed **without** first setting the `LEGAL_REVIEWER` cookie — i.e. as a fresh visitor's very first click on the landing page's own second link, before ever touching the role switcher. Result: **500**, with the dev server log showing an uncaught `ForbiddenError` thrown from `requireRole()` inside the Server Component, with no `error.tsx` boundary anywhere in `apps/web/app` to catch it — it falls through to Next's generic error page.

This does **not** break ROADMAP SC-1 or `docs/DEMO-WALKTHROUGH.md` as documented: the walkthrough's own step 5 ("switch to the legal identity") happens *before* the presenter is expected to reach the review screen, so the cookie is already `LEGAL_REVIEWER` by the time `/assessments` (or `/assessments/{id}`) is actually visited in the prescribed order — confirmed live: with the cookie set first, `/assessments` returns 200. It is also not a regression introduced by this round's fix — the underlying `requireRole` throw-uncaught pattern is pre-existing and consistent across every role-gated page in the app (no `error.tsx` exists anywhere), and was simply unreachable at the (wrong) `/legal/assessments` URL before this round's link fix. Fixing the link is what makes this pre-existing rough edge newly visible for the first time.

Flagged here as a genuine, live-reproduced robustness gap (a stakeholder who deviates from the script — e.g. clicks "Open an assessment, as Legal" as their very first action, which is a completely natural thing for a legal reviewer to do — hits an unstyled Next.js crash page instead of a friendly "switch to Legal first" message), worth a WINDOWS.md entry or a small follow-up (catch `ForbiddenError` in the page / add an `error.tsx`), but **not treated as a gap** against this phase's ROADMAP success criteria, since it doesn't affect the documented, in-scope walkthrough path and mirrors an app-wide pattern rather than a defect specific to this round's changes.

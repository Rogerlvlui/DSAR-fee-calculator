## Accomplishments

- `apps/web/src/domain/verdict-order.ts`: `VERDICT_ORDER`/`compareByVerdict`, the single expression of PRD §10.3's flagged-first card ordering, proven both by a direct map assertion and by the rendered order of a six-line fixture supplied out of order.
- `apps/web/src/server/review-view.ts`'s `buildReviewView()`: per-line provenance detail (category label, quantity/unit/rate, and the applied rule's verification status read from the real, uncoerced `loadDemoPack()`), plus the advisory-deadline computation that falls back to the response deadline for a pack (this one) that sets no separate fee-notification deadline.
- `LineCard`/`MatterRail`/`PackRail`/`TotalsRail`: the full three-region layout — provenance always visible with no disclosure element, matter attestations and every matter-level flag rendered prominently, the pack's open questions listed in full, and the seven-row totals rail (two rows indented) with the headline genuinely absent from the markup while `PENDING > 0`.
- `apps/web/src/domain/disposition-actions.ts`/`review-tallies.ts`: the per-verdict permitted-action map both the client and server read from the same source, the minimum-reason-length rule (10 non-whitespace characters, no stop-list this phase), and the integer-only tallies/final-amount computation that refuses to run while any line is pending.
- `dispositionLine()` (assessments.ts) + `POST /api/assessment-lines/{id}/disposition`: role-checked, then action-permitted-for-verdict, then reason, then amount (bounded by the engine's own amount for a reduction, by the claimed amount for allow-with-amount/allow-anyway) — a refusal writes nothing, proven by re-reading the stored line after every negative test.
- `listBulkAcceptableLineIds()`/`bulkAcceptLines()` + `POST /api/assessments/{id}/bulk-accept`: eligible only for a plain `ALLOW` verdict with a `VERIFIED` rule and a `PENDING` disposition — always empty against the real committed SG-PDPA pack (every category rule is `NEEDS_VERIFICATION`), which is the demo telling the truth per 03.1-UI-SPEC.md's Known Deviation note, not a bug.
- `DispositionControls`/`BulkAcceptBar`: each split into a stateful wrapper (owns `useState`/`useRouter`/`fetch`) and a pure `*View` component, because `useRouter()` throws under a bare `renderToStaticMarkup()` outside a real Next.js request — this module's own tests render the pure half directly.

**4. [Rule 3 - Blocking] Task 3's own "full exclusion matrix in one fixture" acceptance criterion was untestable against the real pack**
- **Found during:** Task 3, while writing its own acceptance-criteria-mandated test

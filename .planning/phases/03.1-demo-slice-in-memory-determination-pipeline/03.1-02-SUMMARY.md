**3. [Rule 4 - Architectural, resolved without escalation] The category select's original design rendered all 21 codes regardless of the categories prop**
- **Found during:** Task 2 (surfaced while writing Task 3's tests)
- **Issue:** The repeater's category `<select>` originally iterated a hardcoded `CATEGORY_GROUPS` list of all 21 codes and looked up each one's label in the `categories` prop, falling back to the bare code string if absent. A test supplying a partial `categories` array (as Task 3's component-scan half needs) would then render spurious codes with no real label — and, more importantly, a category option could render with no pack-sourced label at all.
- **Fix:** Category options now render only for codes present in the `categories` prop, grouped via a derived `GROUP_LABEL_BY_CATEGORY` lookup — production usage is unaffected (the real pack view always supplies all 21), and a test can safely supply a subset.
- **Files modified:** `apps/web/src/ui/intake/expense-line-repeater.tsx`
- **Verification:** `pnpm vitest run --project web -t "REPEATER"` and `--project boundary`, both green; `pnpm run depcruise` clean.

# Phase 03.1 — UI Design Contract

> Visual and interaction contract for the demo slice: HR intake → legal review → sign-off →
> HR result/notice, running against the real engine and the real (coerced-for-compute-only)
> SG-PDPA pack. Derived from `docs/dsar-fee-agent-mockup.html` (Annex A, the CLAUDE.md-locked
> design source), PRD §10, and this phase's demo-specific hard constraints — no CONTEXT.md exists,
> so no product-owner design decisions were re-opened; only gaps the mockup doesn't cover were
> filled by reasonable default.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-authored React components in `apps/web`, styled with Tailwind v4 CSS-first tokens (`@theme`) transcribed from Annex A's CSS custom properties |
| Icon library | none — Annex A uses zero icons anywhere (verdict/state is conveyed entirely by badge text + colour + layout, never a glyph); do not introduce one this phase |
| Font | System stack only, no webfonts, no network fetch — see Typography below |

**Decision (Claude's discretion, noted per the untrusted-input/auto-mode framing — not a legal
question, so not stopped on):** no shadcn. `components.json` does not exist and `apps/web` does
not exist yet, which would normally trigger the shadcn init gate. Declined because (a) CLAUDE.md
requires matching Annex A's structure and hierarchy, which is a fully bespoke, non-shadcn visual
system (custom CSS variables, no Radix primitives), and layering shadcn's defaults on top buys
nothing but rework for a 2-week-out demo; (b) 03.1-RESEARCH.md's Standard Stack never mentions
shadcn — plain Tailwind is already the locked plan. `Component Inventory` and `Registry Safety`
sections are therefore omitted/marked not-applicable per the template's own instruction for
`Tool: none`.

**Decision — fonts:** Annex A's `<link>` to `fonts.googleapis.com` (Newsreader / IBM Plex Sans /
IBM Plex Mono) is exactly the network fetch 03.1-RESEARCH.md Pitfall #5 forbids, and no font
files are vendored in the repo today. Rather than add binary assets this phase, use the fallback
stacks Annex A's own CSS already declares as the *primary* stack — they preserve the same
three-family hierarchy (sans / serif / mono) with zero new assets and zero network calls:
- `--sans`: `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif`
- `--serif`: `ui-serif, Georgia, "Times New Roman", serif`
- `--mono`: `ui-monospace, "SFMono-Regular", Menlo, monospace`

**Known deviation from Annex A's literal data (flag for the executor, not a styling change):**
per 03.1-RESEARCH.md Assumption A2 (rejected by product owner, Option B), the committed
`SG-PDPA/2026.09.1.json` leaves `STAFF_TIME_SEARCH.verificationStatus` as `NEEDS_VERIFICATION` —
unlike Annex A's mockup, where line 1 (`STAFF_TIME_SEARCH`) is shown *verified* (no "unverified
rule" badge, and it is the one line the bulk-accept bar can act on: `Accept verified supported
lines (1)`). In this demo, **all three `ALLOW`/`ALLOW_CAPPED` lines carry the unverified-rule
badge**, and the bulk-accept control will correctly show and stay disabled at **`(0)`**. Build
the badge and the bulk-accept count from the real `verificationStatus` on each line's applied
rule — never hardcode Annex A's `(1)` or omit the badge from line 1.

## Spacing Scale

Declared values (must be multiples of 4) — **govern new, demo-only chrome only**:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-free inline gaps (badge-to-text, inline meta) |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing, page-section gaps |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps between major panels |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level top/bottom spacing |

**Exceptions — deliberate, not a violation:** every component ported from Annex A (status strip,
matter-details panel, attestations, expense-line repeater, review cards, totals rail, sign-off
panel) keeps Annex A's **literal pixel values verbatim**: `6, 7, 9, 10, 11, 12, 13, 14, 15, 18,
20, 22, 28px` appear throughout its padding/gap declarations. CLAUDE.md requires matching Annex
A's structure and hierarchy; those values are the reviewed, locked design source, and renumbering
hundreds of hand-tuned declarations onto a 4/8 grid would only risk visual drift from the mockup
for zero benefit in a demo phase. The 4/8 scale above applies only to genuinely new elements this
phase introduces that Annex A has no equivalent for: the "no persistent data" marker banner, the
HR result/notice screen (Annex A never built §10.4), and the extra "Pack status" strip cell (see
Color/Copywriting below).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 11px | 600 | 1.3 |
| Body | 14px | 400 | 1.5 |
| Heading | 16px | 600 | 1.3 |
| Display | 24px | 600 | 1.2 |

Exactly two weights (400 regular, 600 semibold) and four sizes, by design — Annex A's serif
headings use a webfont-only weight (500) that the system-serif fallback can't reliably render;
Display is simplified to 600 with `letter-spacing: -0.015em` to keep the same "editorial, slightly
condensed" character without depending on a missing font weight.

**Usage mapping (so the executor doesn't have to re-derive it from Annex A):**
- **Display** (`--serif`, 24px/600): page-level `h1.screen` titles ("New fee claim — {ref}",
  "Fee assessment — {ref}"), the first-use capability statement's `<h1>`, and the wordmark. The
  wordmark's trailing "." keeps Annex A's accent-colour treatment (see Color).
- **Heading** (`--sans`, 16px/600): panel/section headers (`.phead` equivalents — "Matter
  details", "Attestations", "What the response cost", "Rule pack", "Sign off"), card titles
  (`.ctitle`).
- **Body** (`--sans`, 14px/400): running text, form inputs, HR's quoted description, reason
  textareas, hint text, basis/citation text. Money and rule-ID/reference values inside body text
  switch to the `--mono` family at the same 14px/400 (a font-family override, not a new size/role
  row) — matches Annex A's `.mono`/`.num` utility classes.
- **Label** (`--sans`, 11px/600, uppercase, `letter-spacing: .07em–.09em`): field labels (`.lb`),
  key/value labels in the status strip and rails (`dt`), badge text, eyebrow/kicker text. Badges
  specifically may go to weight 700 as a bounded exception (Annex A's `.badge` is 700) — this is
  the one place a third weight is tolerated, confined to the 6–8 verdict/status badge strings
  enumerated in the Copywriting Contract, never generalised to running text.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--surface`) | Card/panel backgrounds, form fields — the majority of the visible content area on every screen |
| Secondary (30%) | `#eef0f2` (`--ground`) page backdrop + `#f5f6f8` (`--surface-sunk`) recessed zones | Outer page background; sunk rows (expense-line cards, totals sub-rows, claim footer, resolved-disposition summary boxes) |
| Accent (10%) | `#7c2334` (`--seal`), hover/active `#5e1a27` (`--seal-ink`), wash `#f7ecee` (`--seal-wash`) | Reserved for exactly: primary CTA buttons (Submit to Legal / Sign off / Sign off and release to HR / Continue), the focus-visible outline ring on every interactive element, the wordmark's accent mark, the attestation box's left border and background wash, the sign-off panel's header wash |
| Destructive | `#a32020` (`--stop`), wash `#fbecec` (`--stop-wash`) | Reserved for exactly: the Strike action's button text, the "required" asterisk on mandatory reason fields, the reason-field validation error state (border + counter text) when the ≥10-char/stop-list check fails, the litigation-flag box in the review left rail |

**Neutral text roles** (not counted in the 60/30/10 split, but load-bearing): `--ink` `#171b22`
primary text, `--ink-2` `#3c4450` secondary text/values, `--ink-3` `#6b7480` muted/meta text,
`--ink-4` `#8f97a2` placeholder/disabled text. Borders: `--line` `#d8dce1`, `--line-soft`
`#e6e9ed`.

**Verdict & status semantic colours** — a fourth category, distinct from accent/destructive,
because these are *data-driven* and every one of them carries a **text label**, never colour
alone (WCAG 2.1 AA, already correct in Annex A — preserve exactly):

| Verdict/state | Colour | Wash | Required accompanying text (verbatim) |
|---|---|---|---|
| `FLAG` | `--warn` `#8a5a06` | `--warn-wash` `#fbf1de` (edge `#e0b869`) | "Needs your decision" |
| `ALLOW` | `--ok` `#1c6146` | `--ok-wash` `#e8f2ed` | "Supported by rule" |
| `ALLOW_CAPPED` | `--ok` `#1c6146` | `--ok-wash` `#e8f2ed` | "Supported — reduced to cap" |
| `DISALLOW` | `--deny` `#565f6c` | `--deny-wash` `#eceef1` | "Not supported" |
| Unverified rule | `--warn` `#8a5a06` (dashed border, no fill) | transparent | "unverified rule" |
| Resolved/done | `--ink-2` fill, `--surface` text | — | the specific resolution label (e.g. "Accepted as assessed — SGD 80.00") |
| Pack status = DRAFT (real, this demo) | `--warn` `#8a5a06` | `--warn-wash` | "DRAFT" + the disclosure microcopy below |
| AI-drafted wording | `--ink-3`, dashed border, no fill | transparent | "AI-drafted wording — figures and rule from the engine" |

**New status-strip cell this phase (Annex A has no equivalent):** add a **"Pack status"** cell to
the status strip and to the review screen's rule-pack rail card, between "Rule pack" and
"Authored/reviewed by". It must always render the pack's **real, uncoerced** status — `DRAFT` for
the committed `SG-PDPA/2026.09.1.json` — styled with the `--warn` treatment above, never the
`--ok`/green treatment, regardless of what status the engine-invocation boundary coerces its
in-memory copy to. This is a hard constraint (success criterion 5 / the demo-specific
constraints), not a style choice — see Copywriting Contract for the exact microcopy.

**Mode:** light only this phase. Annex A ships a complete dark-mode token set
(`prefers-color-scheme` + `data-theme="dark"`); carry the token names forward so a later phase can
wire dark mode without renaming anything, but do not build the dark-mode UI now — no success
criterion in this phase asks for it.

## UI Considerations

Applicable state considerations resolved: 14 covered, 4 backstop, 0 unresolved (several
categories were reviewed and explicitly dismissed as out of this phase's scope — see notes below
the table; dismissal is not silence, each carries a reason).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Expense-line repeater (list-collection) | ✅ covered | Renders the "No cost lines yet" / "Add the first line below…" copy (Copywriting Contract) when zero lines exist; Submit to Legal stays disabled per PRD §10.2's existing rule (≥1 line required) |
| zero-one-many | Expense-line repeater locknote badge | ✅ covered | The "{n} lines" locknote is singular/plural-aware ("1 line" vs "N lines"), matching Annex A's `<span class="locknote">6 lines</span>` pattern generalised to any count |
| partial | Expense line missing a conditional field (e.g. third-party not invoiced, no evidence ref) | ✅ covered | Not an intake-side error — flows through unchanged into the review screen as the fixture's own line 5, surfacing as `FLAG`/`CONDITIONS_NOT_MET` per the engine, exactly as Annex A depicts |
| long-text | HR's description, basis, citation on review cards | ✅ covered | All three wrap (never truncate, never an ellipsis) — PRD §10.3 requires the basis/citation "always visible, never behind a disclose triangle"; Annex A's `max-width: 68ch` on `.prov .basis` is the wrap width to keep, not a truncation point |
| overflow | Lawyer's reason textarea | 🧪 backstop | Textarea is vertically resizable (Annex A's `resize: vertical`) and grows with content rather than clipping; verify with a UI-state test typing >200 chars and asserting no `overflow:hidden`/truncation is applied |
| populated | Review cards, six-line fixture | ✅ covered | Ordered `FLAG, FLAG, ALLOW_CAPPED, DISALLOW, ALLOW, ALLOW` per PRD §10.3's explicit rule and Annex A's literal card order — build the sort from `VERDICT_ORDER`, never from fixture position |
| loading | Disposition submit (accept/reduce/strike/allow-anyway/ask-HR) | 🧪 backstop | Button enters a disabled/pending state for the duration of the POST to prevent a double-submit; verify with a test asserting the button is `disabled` while the request is in flight |
| error | Disposition submit failure | ✅ covered | Inline, non-destructive: an error message renders on the card, the card stays `PENDING`/editable, no disposition is recorded — never a silent failure that looks like success |
| loading/error | Bulk-accept submit | ✅ covered | Same pattern as single disposition: all-or-nothing, inline error above the bulk bar on failure, no partial batch commit |
| zero-one-many | Bulk-accept count | ✅ covered | "(n)" is always present and accurate, including `(0)` — the button must render, not disappear, at zero (see Known Deviation note; this demo's real fixture exercises exactly this case) |
| loading | Totals rail recompute after each disposition | ✅ covered (dismissed as N/A) | Totals derive client-side from the already-fetched `Assessment` plus local disposition state — no separate network round-trip, so no loading state is needed here |
| error | Sign-off submit failure | ✅ covered | Inline error near the Sign off button per the new locked string above; matter remains `LEGAL_REVIEW`, no partial sign-off |
| partial | Sign-off acknowledgement checkboxes | ✅ covered | "Sign off and release to HR" stays disabled until every flag requiring acknowledgement is checked, matching Annex A's `ackState()` exactly |
| long-text | Status strip cells (reviewer name, pack id) | ✅ covered | Cells wrap (`flex-wrap`), never truncate a lawyer's name or pack id with an ellipsis — legibility of the accountable identity matters more than a tidy single line |
| overflow | Status strip on narrow viewport | ✅ covered | `flex-wrap: wrap` reflows cells to additional rows, matching Annex A |
| long-text / overflow | Requestor notice draft (copy-to-clipboard block) | 🧪 backstop | Never truncated — full text must be present and selectable/copyable even if it scrolls within its container; verify with a UI-state test using a deliberately long template string |
| empty | Zero-allowable outcome (HR result screen) | ✅ covered | Renders as a normal result ("Recommended fee: {currency} 0.00" / notice stating no fee is charged), explicitly not styled as an error or empty-state placeholder |

**Explicitly dismissed (reason given, not silently dropped):** autosave "saving…" state
(INTAKE-09) — belongs to Phase 5, not required by this phase's five success criteria, and the
single-session demo walkthrough does not depend on it. General N-flag-count layout robustness for
fixtures other than the §14 six-line one — this demo's fixture is fixed; Phase 6 owns the
production review screen's general case. Capability statement long-text/loading — the content is
a static, versioned string, not user- or data-driven, so neither category applies.

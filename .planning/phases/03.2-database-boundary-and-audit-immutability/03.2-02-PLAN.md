Generate a third migration with `pnpm exec prisma migrate dev --create-only --name currency_constraint` and hand-edit its `migration.sql`.

Add a named table constraint on the matter table — name it explicitly, `matter_currency_matches_jurisdiction`, so an application error handler can distinguish this violation from any other — expressed as a nine-way disjunction pairing each jurisdiction enum value with its designated currency enum value: SG with SGD, HK with HKD, AU with AUD, NZ with NZD, JP with JPY, KR with KRW, CN with CNY, IN with INR, VN with VND. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application role → Postgres catalog | Everything the application can do is exactly what this role was granted; the catalog is the authority |
| migration author → applied constraint | What a migration intends and what the database applied are two different facts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-AUDIT | Repudiation | `dsar_runtime` privileges on the audit table | high | mitigate | `grants.test.ts` asserts both the granted `SELECT`/`INSERT` and the withheld `UPDATE`/`DELETE`/`TRUNCATE` from the privilege catalog, complementing plan 01-04's statement-level falsification. Asserting the positive as well as the negative is what stops the test passing against a role granted nothing. |
| T-1-CURRENCY | Tampering | `matter_currency_matches_jurisdiction` | high | mitigate | Named check constraint enumerating the nine pairs, falsified by attempting mismatched inserts; the expected pairs are derived from `JURISDICTION_CURRENCY` so the constraint, the map and the zod refinement cannot drift apart unnoticed. |
| T-1-STATUS | Tampering | the native status enum | medium | mitigate | Label set and order compared against the frozen `MATTER_STATUSES` tuple, plus an attempted out-of-set insert observed to be refused by the database. |
| T-1-CASCADE | Repudiation | every foreign key in the public schema | high | mitigate | `pg_constraint` is queried for the applied referential actions, so a cascading action introduced by a later migration fails a test even if the Prisma source still reads correctly. |
| T-1-DRIFT | Tampering | migration history vs declarative schema | medium | mitigate | `prisma migrate diff --exit-code` is run as an acceptance command, so hand-edited SQL cannot silently diverge from the model the rest of the codebase compiles against. |
</threat_model>

Write `packages/schemas/src/money.ts` exporting:
- `MINOR_UNIT_DECIMALS: Record<CurrencyCode, 0 | 2>` with `JPY: 0`, `KRW: 0`, `VND: 0` and the remaining six at `2`. Author it explicitly and exhaustively — do not derive it from `Intl`, and do not add a default branch. The typed `Record<CurrencyCode, …>` makes a missing currency a compile error, which is the point.
- `formatMinor(value: Minor, currency: CurrencyCode, locale?: string): string`. It reads the decimal count from `MINOR_UNIT_DECIMALS`, derives the major-unit value by dividing by `10 ** decimals` — using that map value, never a hard-coded 100 — and always passes both `minimumFractionDigits` and `maximumFractionDigits` explicitly to `Intl.NumberFormat`. Never rely on the currency-code default path: it depends on the running Node build's ICU variant and is invisible at the call site.
- `minorToMajorParts(value: Minor, currency: CurrencyCode): { units: number; fraction: number }` for callers that need the split without a locale, computed with integer division and remainder so no float touches the arithmetic.

Note in the module header that the division inside `formatMinor` is the terminal display step and is the only division permitted anywhere on the money path.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untyped JSON → zod parse | Every value entering the domain from HTTP, Prisma or a rule-pack JSON file crosses `.parse()` here |
| `number` → `Minor` | The single sanctioned conversion point where an unbranded integer becomes a money value |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-MONEY | Tampering | `MinorSchema`, `toMinor`, `formatMinor` | high | mitigate | `z.number().int().brand<'Minor'>()` makes a bare `number` unassignable; `toMinor()` is the single conversion point; the AC-07a lint rule from plan 01-01 catches any money-named identifier that reverts to `number`; `money.test.ts` asserts `1.5` and `NaN` are rejected rather than rounded. |
| T-1-CURRENCY | Tampering | `JURISDICTION_CURRENCY`, `MINOR_UNIT_DECIMALS` | medium | mitigate | Both are exhaustive `Record<Union, …>` types with no default branch, so a missing or extra jurisdiction/currency is a compile error. Cardinality is additionally asserted at runtime in the tests, which catches a widened union. |
| T-1-ICU | Tampering | `formatMinor` | medium | mitigate | Decimal counts come from an authored map and are always passed explicitly to `Intl.NumberFormat`, so the rendered figure does not vary with the Node build's ICU variant. |
| T-1-PII | Information Disclosure | `PERSONAL_DATA_DENY_LIST` | high | mitigate | The AC-06 deny-list is exported from exactly one module here; plan 01-03's Prisma-field test and Phase 3.2 plan 03.2-03's DOM test both import it, so widening the list automatically widens both checks. |
| T-1-STATUS | Tampering | `MatterStatusSchema` | medium | mitigate | Closed `z.enum` over a `readonly` tuple, cardinality asserted, whitespace and case variants explicitly rejected; plan 01-03 mirrors the same tuple into a native Postgres enum so the closed set holds at the database too. |
</threat_model>

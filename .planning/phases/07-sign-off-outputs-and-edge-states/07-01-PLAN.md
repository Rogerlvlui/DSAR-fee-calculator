<objective>
Prove the internal-record PDF architecture end to end on the thinnest possible path, and close
the highest-risk technical unknown in this phase before any layout work is invested.

`packages/documents` does not exist; no PDF generation exists anywhere in this repository; no
Route Handler in this codebase has ever returned a non-JSON body; and `07-RESEARCH.md`
Pitfall 4 records a real, currently-open upstream bug (`diegomura/react-pdf#3285`) that
reproduces for exactly this monorepo shape — `@react-pdf/renderer` imported through an external
workspace package and rendered from a Next.js App Router Route Handler.

Purpose: one production-quality vertical slice — new workspace package, pure view module,
`@react-pdf/renderer` document, binary Route Handler, role gate, and every piece of build /
test / lint scaffolding a new package needs — carrying a real end-to-end verify, including one
that goes over real HTTP through the app's own bundler rather than calling the handler
function directly. Every line written here survives into the finished record; the dense table
(07-04) and the download trigger (07-05) expand outward from it.

Output: a downloadable one-page PDF for a signed-off assessment, refused for HR and refused
before sign-off, with the disclosure footer already on the page.
</objective>

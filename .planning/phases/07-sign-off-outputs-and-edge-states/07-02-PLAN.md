<objective>
Close the sign-off gate: correct a verified wrong status code, make the refusal say which
lines are outstanding, and add the one genuinely new precondition this phase owns.

`07-RESEARCH.md` verified by direct code read that `signOff()` throws `ValidationError` (400)
for the still-PENDING case while AC-16 explicitly requires 409, and that
`tests/routes/signoff.test.ts` currently asserts the wrong behaviour. The current message is a
bare sentence with no line list. Separately, nothing anywhere checks whether the actor about to
sign off is the actor who last activated the pinned pack version (PACK-08 / AC-41b).

Purpose: a lawyer refused at sign-off must be told exactly what is outstanding, with a status
code a caller can distinguish from a malformed request; and a lawyer must not be able to sign
off an assessment resting on a pack version they themselves activated.

Output: a corrected, line-naming 409 refusal; a consistent 409 for the acknowledgement
precondition; a new 403 activation-conflict guard; and route-level proof of the full SignOff
record's field set and of the ACCESS-04 role refusal.
</objective>

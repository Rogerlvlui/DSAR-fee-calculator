<planner_decisions>
**PD-3 — `appliesTo` for a stub follows the frozen schema's own documented derivation: every controller type whose posture is not `PROHIBITED`.** `RulePackSchema`'s comment states that derivation outright, and it is the value `packages/engine/src/preconditions.ts` reads to decide whether `assess()` runs at all. Deriving it any more narrowly — excluding `NO_EXPRESS_AUTHORITY` as well — would make PRD §7.4's stated behaviour for that posture ("every line returns `FLAG`, the draft baseline is zero") unreachable, because the matter would be refused at the precondition instead of flagged. Refusing where the PRD says flag would read directly against PRD §0's fourth non-negotiable. So: `PROHIBITED` excludes a controller type from `appliesTo`; `NO_EXPRESS_AUTHORITY` does not.

The HK pack (plan 03-05) is the one exception and stays verbatim per D-14: PRD §7.5 ships `appliesTo: ["PRIVATE_ORGANISATION"]` while its `PUBLIC_AGENCY` posture is `NO_EXPRESS_AUTHORITY`, which is narrower than this derivation. That divergence is transcribed as written and recorded in that pack's `openQuestions`, not silently reconciled.

Every row this plan adds carries `packKind: "stub"`. Plan 03-05 adds `HK-PDPO` and `SG-PDPA` to the same table with `packKind: "authored"`, so every assertion here that is about the stub set specifically must filter on `packKind`, not assume the table and the stub set are the same list.
</planner_decisions>

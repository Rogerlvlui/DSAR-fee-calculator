<planner_decisions>
**PD-4 — HK's `flatFee.amount` is committed as `0`.** `FlatFeeSchema.amount` is a required, non-nullable `Minor`, so the key cannot be present without an integer, and D-22 requires the extension to ship while D-14 forbids authoring a figure the PRD does not state (it states none — §7.5 carries only the advisory `HK.FLAT_FEE_CHECK` prose). Zero is chosen precisely because it is not a plausible fee: an illustrative figure like 50000 is indistinguishable, to a future reader, from a researched one, which is the exact failure mode D-14 and D-15 exist to prevent. Research's Pitfall 5 proposed an illustrative placeholder; this rejects that half of the proposal and keeps the other half — the `verificationNote` channel — which is what D-22 actually locked. The token in `verificationNote` blocks ACTIVE, so the zero can never reach an assessment.

**PD-5 — three HK transcription deviations are recorded in the pack's `openQuestions` rather than resolved silently.** (i) `HK-PDPO.STAFF_TIME_LEGAL_REVIEW`'s basis as printed in §7.5 contains a `LEGAL_CONCLUSION_BANNED_WORDS` member in lowercase, so AC-32a and D-14 collide on that one sentence; the narrower, testable requirement wins and the phrase naming counsel's advice is reworded, preserving the rule's substance exactly. (ii) `HK-PDPO.STAFF_TIME_REDACT_THIRD_PARTY`'s basis contains an adverbial inflection of a banned word that the canonical word-boundary matcher does not catch; CONTEXT.md binds this phase to reuse that matcher and author no second one, so the sentence ships verbatim and the gap is flagged for counsel. (iii) §7.5's `appliesTo` is narrower than `RulePackSchema`'s own documented derivation. All three are questions for the authoring lawyer, which is what `openQuestions` is for.
</planner_decisions>

<objective>
Make "is this pack currently usable?" a derived answer and "which version was this assessment pinned to?" a deterministic lookup.

Purpose: AC-39's hard stop is the PRD's own statement that "a silently stale rule pack is the most likely way this product produces a wrong answer at scale", and AC-40 depends on a pinned version resolving to the same content forever. Both are properties of the repository layer and neither needs a database.
Output: `stale.ts` reusing the engine's calendar arithmetic, `resolveRulePack` on the loader, and the fixtures proving a new version disturbs nothing.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored `status` field → usability decision | The stored literal is an authored lifecycle value; time passing is not an authored event, so currency must be recomputed at the point of use |
| pinned `rulePackVersion` → resolved pack content | The join between an assessment and the rules it was computed under; if this drifts, the defensibility claim the whole product rests on fails |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12 | Tampering | stored `status` literal | high | mitigate | `deriveEffectiveStatus` recomputes currency from `reviewDueOn` against an injected `now` on every read and never trusts a stored `ACTIVE`; a repository file cannot flip its own status when a date passes, so any design reading `status` alone would silently accept a pack AC-39 requires refused. |
| T-03-13 | Tampering | pinned version resolution | high | mitigate | `resolveRulePack` asserts the parsed pack's own `packId` and `version` match the request, so a file moved or renamed into the wrong directory fails loudly instead of answering a pin with the wrong rules. Proven by the two-root fixture comparison. |
| T-03-14 | Information disclosure | `staleReason` text | low | mitigate | The reason names a date and nothing else, and is asserted banned-word-free by the same matcher the pack validator uses, so a staleness notice cannot become a statement about legality. |
| T-03-15 | Tampering | `@dsar/rulepacks` → `@dsar/engine` edge | medium | mitigate | The new dependency runs rulepacks-to-engine only; every `.dependency-cruiser.cjs` purity rule is anchored `from: ^packages/engine`, and `pnpm run depcruise` is a task acceptance criterion so a reversed edge would fail the build. |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new external package is introduced; the only `pnpm install` run is a workspace relink after adding an internal `workspace:*` dependency. No legitimacy checkpoint is required. |
</threat_model>

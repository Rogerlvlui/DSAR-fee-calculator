<objective>
Three things, in one pass, in dependency order.

**One — the CSS pipeline is dead.** `apps/web/app/globals.css` declares a complete, well-formed
Tailwind v4 theme, but no PostCSS plugin ever processes it. Confirmed at source: no
`postcss.config.*` exists anywhere in the repo, and the root `package.json` carries
`tailwindcss@4.3.3` with no companion plugin. Confirmed at the output end: the committed build
artifact `apps/web/.next/static/chunks/25vb8k01b4hj3.css` is 1,948 bytes of the source stylesheet
passed through verbatim — the theme at-rule survives un-expanded and not one utility class is
generated. Browsers ignore that at-rule, so every screen currently renders in Times New Roman with
no colour, no card, no spacing. Every design token in the repo has been inert since it was written.

**Two — the demo Legal reviewer is renamed** to the product owner, Roger Lui, across one source
file and six test files (14 literal occurrences).

**Three — the mockup's visual language is applied** to the priority screens. The gap is not the
tokens: the mockup's maroon, green and amber are already byte-identical to `--color-seal`,
`--color-ok` and the `--color-warn` family. The gap is that nothing consumes them. The markup
already reaches for nineteen bespoke semantic class names (`screen`, `kicker`, `hint`, `row`, `why`,
`posture`, `claimfoot`, `fig`, `wordmark`, …) that **no stylesheet in this repo has ever defined**.
The components were written for a component layer that was never authored.

Purpose: the app has real architecture, real gates and real legal logic behind a screen that looks
broken. This makes what is already built legible.

Output: a working PostCSS pipeline with a permanent regression gate; a renamed demo identity; a
component layer in `globals.css` built strictly from the existing tokens; and that layer applied to
the legal review screen, the HR intake screen and the HR result screen.
</objective>

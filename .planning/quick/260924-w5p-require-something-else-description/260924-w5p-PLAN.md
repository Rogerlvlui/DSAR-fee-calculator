# Quick task: require a real description on "Something else" cost lines

**Why:** Product owner asked whether HR can describe a "Something else" (`OTHER_UNCLASSIFIED`)
line. The box already exists — every line's "What this cost was for" (`ExpenseLine.description`,
PRD §6.2, max 300) is quoted to Legal as "HR's description". But for an `OTHER_UNCLASSIFIED`
line, which is always FLAGged (AC-19) and has no rule to lean on, that description is the only
thing Legal classifies it from, and the form accepted a single character ("x"); the server
accepted an empty string. No new field (PRD §7: no free-text category field); `hrNote` stays
unexposed.

**Task 1.** `apps/web/src/domain/expense-description.ts`: `hasSufficientDescriptionForCategory`
(OTHER_UNCLASSIFIED needs ≥10 non-whitespace chars, same counting as the disposition-reason
rule) and the HR hint text (describe the cost; check whether a listed category fits, e.g. courier
→ "Postage, courier, delivery"; no names/addresses).

**Task 2.** Intake: `computeIntakeDisabledReason` names the under-described line by number;
`expense-line-repeater.tsx` shows the hint under the category select and an inline "Required"
counter while short, marks the input `required`/`aria-invalid`.

**Task 3.** Server: `addExpenseLine` and `replaceExpenseLine` refuse a short description on an
OTHER_UNCLASSIFIED line with `ValidationError` (400).

**Verify:** unit test for the rule, two `computeIntakeDisabledReason` cases, a route test proving
a direct POST is refused/accepted; typecheck, test, lint, depcruise; live browser check through
to Legal's review card.

# Quick task: combine the Legal and DPO demo identities into one ("Privacy Lawyer"), delete Wei Ling Ong

**Why:** Product owner request — simplify the demo role switcher from 3 identities to 2.
Roger Lui's demo identity should carry both `LEGAL_REVIEWER` access (review/sign-off) and
`DPO_ADMIN` access (`/admin/audit`), renamed to "Roger Lui — Privacy Lawyer, Singapore".
The separate `DPO_ADMIN` identity ("Wei Ling Ong") is deleted from the demo entirely.

**Not touched:** `packages/schemas`'s frozen `RoleSchema` (DPO_ADMIN stays a valid Role
value — only the demo's *identity* mapping changes, not the type system) and
`prisma/schema.prisma`'s native enum. This is a demo-identity consolidation, not a schema
change.

**Task 1 — widen the audit-export gate, retire the DPO_ADMIN demo identity.**
- `apps/web/src/server/data/auth.ts`: remove `DPO_ADMIN_USER` and its comment; rename
  `LEGAL_REVIEWER_USER.displayName` to `"Roger Lui — Privacy Lawyer, Singapore"`; remove
  `DPO_ADMIN` from `DEMO_USERS`' type and object; remove the `"DPO_ADMIN"` branch from
  `resolveActorFromCookieHeader` (an unrecognised cookie value already falls back to
  `HR_PREPARER` — this is the correct outcome once the identity is retired, not a gap);
  widen `requireRole(actor, role: Role)` to `requireRole(actor, role: Role | Role[])`,
  checking membership.
- `apps/web/src/server/data/audit.ts`: change `requireRole(actor, "DPO_ADMIN")` to
  `requireRole(actor, ["DPO_ADMIN", "LEGAL_REVIEWER"])`; update the nearby comment.
- `apps/web/app/layout.tsx`: remove the `DPO_ADMIN` entry from `ACTOR_OPTIONS`; update the
  comment above it.
- `apps/web/app/admin/audit/page.tsx` and `apps/web/src/server/data/audit-trail.ts`:
  update comments referencing "DPO_ADMIN-gated" to reflect the combined-role gate (no
  behavior change in these two files — they still just inherit `exportAuditLog`'s gate).

**Task 2 — update tests that depended on the separate DPO_ADMIN identity.**
- `tests/routes/audit-export.test.ts`: this file's entire premise was "the DPO_ADMIN demo
  identity" — rewrite it around the Legal reviewer's now-combined access. Keep the property
  "an actor without the required role is refused" (HR_PREPARER case, unchanged) but flip
  "reviewer is refused" to "reviewer succeeds" (Legal now has audit-export access). Repoint
  every `officer`/DPO_ADMIN-cookie construction at `DEMO_USERS.LEGAL_REVIEWER`. Add one new
  test proving a hand-built actor with `role: "DPO_ADMIN"` (constructed directly, not via
  `DEMO_USERS` — that identity no longer exists) is *also* still accepted, so the array-based
  gate's DPO_ADMIN branch keeps real test coverage even with no demo persona attached to it.
  Add one test proving the `"DPO_ADMIN"` cookie value is no longer recognised (falls back to
  `HR_PREPARER`) — proof the retirement was done correctly, not left as a silent escalation
  path.
- `tests/routes/signoff.test.ts`: delete the `DPO_ADMIN role cookie` sub-test (ACCESS-04) —
  its property (non-`LEGAL_REVIEWER` refused with 403, nothing leaked) is already fully
  covered by the `HR_COOKIE` case directly above it; after the identity retirement, the
  `DPO_ADMIN` cookie value resolves to the *same* `HR_PREPARER` fallback actor, making this
  a duplicate of that case rather than independent coverage. Remove the now-unused
  `DPO_COOKIE` constant too.
- `tests/routes/matter-submitted-authorization.test.ts`: delete the
  `getHrMatterStatus(DEMO_USERS.DPO_ADMIN, ...)` assertion — the same test already asserts
  the identical property via `DEMO_USERS.LEGAL_REVIEWER` on the line above it.
- `apps/web/src/ui/admin/audit-trail-view.test.tsx`: this file's `ACTOR` fixture (line
  22-26) is synthetic test data representing a *past audit event's actor* (who performed a
  historical action), unrelated to the demo role switcher — but its `displayName` literally
  reuses "Wei Ling Ong". Rename it to a clearly-synthetic placeholder so no trace of the
  retired identity's name remains anywhere in the codebase.

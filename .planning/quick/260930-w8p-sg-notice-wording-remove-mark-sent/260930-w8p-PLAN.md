# Quick task: counsel-authored Singapore notice wording; remove "Mark notice sent"

**Why:** Counsel (Roger Lui) has authored the Singapore requestor-facing notice. Until now
the HR result screen showed "Counsel has not yet authored the requestor-facing wording for
this jurisdiction…" because SG-PDPA's `requestorNoticeTemplate` carried the UNAUTHORED marker.
The product owner also wants the "Mark notice sent" button removed from the HR result screen.

**Legal decisions (counsel, 2026-09-30, asked per CLAUDE.md):**
- Singapore only. HK-PDPO and every stub pack stay UNAUTHORED.
- Counsel's wording is used as written, including "the finalized fee". This replaces PRD
  §10.4's "for Singapore, framed as a written estimate". Recorded in §10.4.

**Implementation decisions:**
- `[amount]` is replaced with the assessed fee, and `[date]` with the matter's
  request-received date ("25 Sep 2026"). `[Name]` always stays a literal placeholder: the
  system must never hold the requestor's name (NS-4), so HR fills it in from their own mailbox.
- The letter stays below the Reference / Amount / "What this covers" block, which is what its
  "set out above" refers to.
- Removing the button is UI only. The `/api/matters/[id]/notice-sent` route and the
  SIGNED_OFF → CLOSED transition stay. The watermark and boundary note stay. Recorded in PRD
  §10.4 as a product-owner decision.

**Task 1.** SG-PDPA pack: set `requestorNoticeTemplate`. The pack stays DRAFT.
**Task 2.** `notice-draft.ts`: substitute `[amount]`/`[date]`; `display-date.ts`: format an ISO
calendar date without re-reading it through a time zone. Update the callers.
**Task 3.** `notice-block.tsx`: drop the button, its fetch and its state; update the page and tests.
**Task 4.** PRD §10.4, DEMO-WALKTHROUGH.md.

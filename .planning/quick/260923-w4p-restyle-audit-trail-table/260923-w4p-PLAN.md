# Quick task: restyle the Audit trail tables to match the design

**Why:** Continuing a systematic pass (product owner request) through the remaining screens
against `docs/design/dsar-fee-agent-claude-design.dc.html` after the status-strip fix. Found
that `audit-trail-view.tsx`'s two event tables render with no bordered card wrapper and no
shaded header row — the design wraps its "Events" table in a white card with a header bar
and `background: #f5f6f8` column headers. Confirmed via DOM inspection (`th` background
`rgba(0,0,0,0)`, table wrapper `border: 0px`) and by reading the component's own header
comment: it deliberately reused `.notice-table` (07.1-02) for its ready-made borders — but
that class is the requestor-facing document's intentionally plain, undecorated look, not a
data-table treatment.

**Task 1.** Add `.data-table-card` and `.data-table` to `apps/web/app/globals.css`
(`@layer components`), independent of `.notice-table` so the letter-styled document is
untouched: bordered card, a header-bar `.eyebrow` (reusing the existing label style),
shaded `thead th` (`--color-surface-sunk` background, uppercase small-caps), bottom-bordered
`td`. Update `audit-trail-view.tsx`: wrap each `<section>` in `className="data-table-card"`,
change both `<table>`s from `notice-table` to `data-table`, remove the now-redundant
`className="hint"` from each `<th>` (handled by the `.data-table th` selector instead).

**Verify:** `pnpm typecheck`, `pnpm test` (no regression expected — `audit-trail-view.test.tsx`
asserts on rendered text/values, not markup classes), live browser check against the design.

**Done:** the Audit trail screen's two tables render as bordered cards with shaded header
rows, matching the design — confirmed live, not just that the CSS class exists.
